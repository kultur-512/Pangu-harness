## 1. 应用场景与业务价值

**场景主线：软件工程长期维护。** 真实业务问题：一次"为客户持续维护代码库"的工程师会话往往跨很多轮需求——早期定下的设计约束，到第 N 轮加新功能时被悄悄破坏；跨文件的关联修改随着上下文窗口滚动丢失前文；进程中断后要从头回忆进度。这些正是命题点名的"中期遗忘 / 上下文断裂"，对应的业务价值：
- 早期需求/约束长期不被破坏 → 减少返工与隐性回归（质量/成本）；
- 跨文件长文档关联正确引用 → 减少人工复查（效率）；
- 中断后可准确续接 → 长周期任务可持续跟踪（项目管理/客户服务）。

### 2.3 指标定义

| 指标 | 定义 | 度量方式 |
|---|---|---|
| **约束召回率** | 埋点约束在后续回合被正确引出的比例 | 人工/脚本对回复断言 |
| **约束遵循率** | 产出代码/补丁是否破坏该约束 | 脚本断言（静态检查/测试） |
| **跨文件关联命中率** | 需引用文档 A 的修改在 B 中是否做对 | 脚本断言 |
| **状态续接准确率** | resume 后模型自述"当前进度/未决/下一步"与真实状态吻合度 | 人工评分(0-1) |
| **记忆卡利用率** | 注入的记忆卡中被实际相关引用的比例（减污染） | 接口契约 v3 口径：7B 档 [M1] 卡号引用实验（若 U6 可跑）**或** markVerified 文件交集率（工具写入/验证文件 ∩ 卡 referencedFiles，机器判定）——二选一写死，不混用 |
| token/时间/成本 | 每档任务完成耗用 | usage 统计 |

### 2.4 控制变量

- 同任务同种子跑 A/B/C；A/B/C 除记忆注入差异外，档位/预算/温度一致。
- 记录：openPangu 具体模型与版本、端点部署（昇腾/本机）、上下文窗口、每档任务量、随机种子、总 token 与成本。
